# Extra contour regression

Open `viewer.html` locally to inspect the GeoJSON routes point by point. It is
self-contained and can load other GeoJSON LineStrings. `comparison.svg` is the
rendered side-by-side view inspected during this fix.

Inputs: start/end `(0,0)`, outer square `(0,0)-(10,10)`, no obstacles, width 1,
overlap 10%. Coordinates are Cartesian; they are not geographic measurements.

- `before.geojson`: generated by core `edbab69`, 31 points, length 194.142136.
- `after.geojson`: generated after removing the per-cell contour, 27 points,
  length 154.142136. The 40-unit perimeter lap is gone; the diagonal home remains.

The public API regression also checks a minimal 2×2 square with width 1 and
opposite-corner endpoints: three height-2 cuts plus two unit links total 8.
Sweep tests check that every variant crosses the cell horizontally only once.
Rectangular disk coverage, safe concave connections and obstacle avoidance
remain covered by the existing suites. Removing the contour also removes its
previous disk-coverage guarantee at arbitrary inclined or sharp boundaries.

Validation on 2026-10-16: 10/10 CTest checks passed in Debug and with ASan,
UBSan and LeakSanitizer. LeakSanitizer was run outside the ptrace sandbox.
